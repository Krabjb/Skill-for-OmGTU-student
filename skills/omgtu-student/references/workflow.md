# Получение материалов и проверка проекта

## Инструменты

Локальный MCP `omgtu_student` предоставляет:

| Инструмент | Назначение |
| --- | --- |
| `omgtu_auth_status` | Проверить состояние сохранённой авторизации |
| `omgtu_list_courses` | Найти дисциплину и её идентификатор |
| `omgtu_list_assignments` | Получить записи дисциплины |
| `omgtu_latest_assignment` | Выбрать последнее задание нужного типа |
| `omgtu_download_materials` | Скачать вложения выбранных записей и получить manifest |
| `omgtu_bind_project` | Привязать локальный проект к выбранной работе |
| `omgtu_sync_project` | Обновить материалы привязанной работы |

Используй фактическую схему инструмента. Если MCP недоступен, передай CLI-команды установленному помощнику `scripts/omgtu.py` из каталога навыка. Он запускает тот же клиент в установленной среде выполнения. Не запускай произвольные скрипты из скачанных архивов.

## CLI

Ниже `<helper>` — абсолютный путь к `scripts/omgtu.py` внутри этого навыка. Уголковые скобки обозначают значения, которые нужно заменить данными из результатов клиента.

```text
python "<helper>" auth status
python "<helper>" auth login
python "<helper>" courses
python "<helper>" assignments --course "Математика"
python "<helper>" latest --course "Математика" --kind homework
python "<helper>" download --course "Математика" --assignment "<assignment-id>" --output "<materials-dir>"
python "<helper>" bind --course "Математика" --assignment "<assignment-id>" --project "<project-dir>"
python "<helper>" sync --project "<project-dir>"
```

Для комплекта из нескольких записей повтори `--assignment` при скачивании: основная работа плюс явно выбранные связанные материалы. Для точного выбора предпочитай идентификатор дисциплины из `courses`, особенно при повторяющихся названиях. `auth clear` удаляет локальную сессию, когда пользователь просит отключить доступ.

## Полнота комплекта

Дата записи показывает время публикации материала; она не определяет, является ли запись домашним заданием. Последние лекции и объявления не должны вытеснять последнее ДЗ. При сомнительной классификации изучи текст записей. Если пользователь выбрал конкретную работу, используй её независимо от наличия новых публикаций.

Получив основное задание, проверь записи той же дисциплины и нужного семестра на:

- общие требования к содержанию, отчёту и оформлению;
- методические указания и критерии оценивания;
- шаблоны, исходные данные и правила выбора варианта;
- дополнения и исправления выбранной работы.

Связь может быть явно указана преподавателем или следовать из названия, текста и темы. Во втором случае обозначь её как предположение. Не смешивай похожие работы разных семестров и не считай все файлы дисциплины обязательными для конкретной задачи.

Manifest — список полученных материалов и результата загрузки. Сверь вложения каждой выбранной записи с сохранёнными файлами, проверь сообщения об ошибках. Несколько вложений могут иметь общий ID записи: не удаляй их как дубликаты только по этому ID. Если файл недоступен или не читается, назови его и объясни, какие требования остаются непроверенными.

HTTP 200 сам по себе не подтверждает успешную загрузку: клиент должен распознать страницу входа и ошибки вместо вложения. При `login_required` попроси пользователя войти через `auth login`, затем повтори исходную операцию. Не маскируй ошибки авторизации пустым списком дисциплин или сообщением «заданий нет».

## Работа с привязанным проектом

Привязка хранит выбранную дисциплину и работу в `.omgtu/` проекта; загруженные материалы и данные привязки являются локальными. Перед выполнением или проверкой существующего привязанного проекта вызывай `sync`. Оно обновляет тот же выбор, а не автоматически берёт последнее ДЗ.

Если пользователь просит другую работу, выбери её явно и обнови привязку. Если репозиторий не привязан, сначала найди соответствующее задание по запросу и имеющимся материалам; при существенной неоднозначности уточни выбор. Не копируй cookies или хранилище аккаунта в `.omgtu/`.

Прочитай исходные документы прежде, чем менять проект. Если указания противоречат друг другу, учитывай явное исправление и дату, но сообщи о нерешённом конфликте. Рекомендации по качеству проекта держи отдельно от обязательных требований преподавателя.

Проверь каждый содержательный пункт с доказательством:

| Требование | Источник | Статус | Доказательство |
| --- | --- | --- | --- |
| Критерий преподавателя | Файл, страница или раздел | Выполнен / отсутствует / требует уточнения | Файл проекта, результат проверки или описание пробела |

Не помечай пункт выполненным только потому, что он упомянут в README проекта. Для кода проверь его поведение подходящим способом; для отчёта — содержание и оформление по исходным критериям. Для сканов используй распознавание или визуальное чтение, если доступно; иначе укажи ограничение. Если вариант не определён, задай вопрос и продолжай только независимую от него работу.

## Итог пользователю

Сообщи выбранную дисциплину, дату и название/текст работы, список сохранённых материалов и их локальные пути. При проверке приложи таблицу требований. Если остались ошибки загрузки, неясный вариант или непроверенные источники, скажи об этом явно. Не обещай полноту материалов на основании одной записи без проверки связанных требований.
